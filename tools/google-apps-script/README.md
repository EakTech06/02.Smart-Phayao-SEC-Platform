# คู่มือติดตั้ง Google Workspace Bridge (Apps Script) สำหรับมือใหม่

คู่มือนี้พาเชื่อมระบบ Smart Phayao SEC Platform เข้ากับ Google Workspace ขององค์กรทีละขั้น
ใช้เวลาประมาณ 30–45 นาที ไม่ต้องเขียนโค้ดเอง แค่คัดลอกและวาง

## ภาพรวม: ทำไมต้องมี "Bridge"

โฮสต์ของระบบ (Shared Hosting) คุยกับ Google ตรงๆ ไม่สะดวก เราจึงสร้าง **Apps Script Web App** หนึ่งตัว
ไว้ในบัญชี Google ขององค์กร ทำหน้าที่เป็น "ตัวกลาง" (Bridge)

```
ผู้ใช้ ──► ระบบ Smart SEC (โฮสต์) ──(cURL + ลายเซ็นลับ)──► Apps Script ──► Google Shared Drive / Calendar / Gmail
```

| งานในระบบ | Bridge ไปทำที่ |
|---|---|
| อัปโหลด/ดาวน์โหลด/ลบไฟล์แนบ | Google Shared Drive |
| กิจกรรม "ทั้งองค์กร" ในปฏิทินกลาง | Google Calendar ขององค์กร |
| อีเมลแจ้งเตือน (เช่น คำขอ PDPA) | Gmail ของบัญชีที่ติดตั้ง |

ทุกคำขอจากระบบจะแนบ **ลายเซ็นที่สร้างจากคีย์ลับ (SHARED_SECRET)** คนที่ไม่รู้คีย์นี้จะเรียกใช้ Bridge ไม่ได้
แม้จะรู้ URL ก็ตาม

---

## สิ่งที่ต้องเตรียมก่อนเริ่ม (Checklist)

- [ ] **บัญชี Google Workspace ขององค์กร** (อีเมลโดเมนหน่วยงาน ไม่ใช่ @gmail.com ส่วนตัว)
      แนะนำให้สร้าง **บัญชีกลางสำหรับระบบ** เช่น `smartsec-bot@py-sec.ac.th`
      เพราะถ้าใช้บัญชีของบุคคล เมื่อคนนั้นย้ายหรือลาออกแล้วบัญชีถูกปิด ระบบจะใช้ไฟล์ไม่ได้ทันที
- [ ] สิทธิ์สร้าง **Shared Drive** (ถ้าไม่มี ขอผู้ดูแล Google Workspace ขององค์กรสร้างให้)
- [ ] เข้าถึงไฟล์บนโฮสต์ได้ (cPanel → File Manager หรือ FTP) เพื่อแก้ไฟล์ `config/local.php`
- [ ] คอมพิวเตอร์ที่ติดตั้ง XAMPP (ใช้สร้างคีย์ลับ) หรือใช้วิธีอื่นในขั้นที่ 4
- [ ] เปิดไฟล์ `tools/google-apps-script/Code.gs` จากโปรเจกต์ไว้ (จะคัดลอกไปวาง)

> 💡 ระหว่างทำ ให้เปิดไฟล์ Notepad ไว้จดค่าที่ต้องใช้ 4 ค่า:
> `ROOT_FOLDER_ID`, `CALENDAR_ID`, `SHARED_SECRET`, `Web app URL`

## ขั้นที่ 1: สร้าง Shared Drive และโฟลเดอร์เก็บไฟล์

1. เข้า https://drive.google.com ด้วย **บัญชีกลาง** (ดูมุมขวาบนว่าล็อกอินถูกบัญชี)
2. เมนูซ้าย คลิก **ไดรฟ์ที่แชร์ (Shared drives)** → ปุ่ม **+ ใหม่ (New)**
3. ตั้งชื่อ เช่น `Smart SEC Platform` → **สร้าง**
4. เข้าไปใน Shared Drive ที่สร้าง → คลิกขวาที่พื้นว่าง → **โฟลเดอร์ใหม่** ตั้งชื่อ `SmartSEC-Files`
5. ดับเบิลคลิกเข้าโฟลเดอร์ `SmartSEC-Files` แล้วดูที่ **แถบที่อยู่ (URL)** ของเบราว์เซอร์:

   ```
   https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz123456
                                          └────────── ROOT_FOLDER_ID ──────────┘
   ```

   คัดลอกส่วนหลัง `/folders/` (ไม่รวม `?usp=...` ถ้ามี) จดไว้เป็น **ROOT_FOLDER_ID**

6. **ตรวจสิทธิ์ของบัญชีกลาง:** ที่ชื่อ Shared Drive → **จัดการสมาชิก (Manage members)**
   บัญชีกลางต้องมีบทบาท **ผู้จัดการ (Manager)** หรือ **ผู้จัดการเนื้อหา (Content manager)**
   (บทบาท "ผู้มีส่วนร่วม/Contributor" ลบไฟล์ไม่ได้ ระบบจะลบไฟล์ไม่สำเร็จ)

> ⚠️ อย่าแชร์โฟลเดอร์นี้ให้บุคลากรทั่วไป ผู้ใช้ทุกคนเข้าถึงไฟล์ผ่านระบบ Smart SEC ซึ่งตรวจสิทธิ์ให้แล้ว
> ระบบจะสร้างโฟลเดอร์ย่อยให้เอง เช่น `core/2026-11`, `pdpa/2026-11`

## ขั้นที่ 2: สร้าง Google Calendar ขององค์กร (ไม่บังคับ)

ข้ามขั้นนี้ได้ถ้ายังไม่ต้องการซิงก์ปฏิทิน (ปฏิทินกลางในระบบยังใช้งานได้ตามปกติ)

1. เข้า https://calendar.google.com ด้วย **บัญชีกลาง**
2. แถบซ้าย หัวข้อ **ปฏิทินอื่นๆ (Other calendars)** → กด **+** → **สร้างปฏิทินใหม่ (Create new calendar)**
3. ตั้งชื่อ เช่น `ปฏิทินกลาง ศูนย์การศึกษาพิเศษ` → เขตเวลา **(GMT+07:00) เวลาอินโดจีน - กรุงเทพ** → **สร้างปฏิทิน**
4. แถบซ้าย ชี้ที่ชื่อปฏิทินใหม่ → จุด 3 จุด → **การตั้งค่าและการแชร์ (Settings and sharing)**
5. เลื่อนลงไปหัวข้อ **ผสานรวมปฏิทิน (Integrate calendar)** → คัดลอก **รหัสปฏิทิน (Calendar ID)**
   หน้าตาประมาณ `c_abc123...@group.calendar.google.com` จดไว้เป็น **CALENDAR_ID**
6. (แนะนำ) หัวข้อ **สิทธิ์การเข้าถึงกิจกรรม** → เปิด **"ให้ทุกคนในองค์กรใช้ได้"**
   เพื่อให้บุคลากรเพิ่มปฏิทินนี้ไปดูใน Google Calendar ของตัวเองได้

## ขั้นที่ 3: สร้างโปรเจกต์ Apps Script และวางโค้ด

1. เข้า https://script.google.com ด้วย **บัญชีกลาง** → กด **+ โปรเจกต์ใหม่ (New project)**
2. คลิกชื่อ **"โปรเจกต์ที่ไม่มีชื่อ" (Untitled project)** มุมซ้ายบน → ตั้งชื่อ `SmartSEC Bridge` → **เปลี่ยนชื่อ**
3. ในไฟล์ `Code.gs` ที่เปิดอยู่ มีโค้ดตัวอย่าง `function myFunction() {...}`
   กด `Ctrl + A` แล้ว `Delete` ให้ว่างทั้งหมด
4. เปิดไฟล์ `tools/google-apps-script/Code.gs` จากโปรเจกต์ (ด้วย Notepad หรือ VS Code)
   → `Ctrl + A` → `Ctrl + C` → กลับมาที่ Apps Script → `Ctrl + V`
5. กด **💾 บันทึก (Ctrl + S)**

## ขั้นที่ 4: สร้างคีย์ลับ (SHARED_SECRET)

คีย์ลับคือรหัสยาวๆ ที่ **ทั้ง Apps Script และโฮสต์ต้องใช้ค่าเดียวกันทุกตัวอักษร**

**วิธี ก — ใช้ XAMPP บนเครื่อง Windows (แนะนำ)**

1. กด `Win + R` พิมพ์ `cmd` → Enter
2. วางคำสั่งนี้แล้วกด Enter:

   ```
   C:\xampp\php\php.exe -r "echo bin2hex(random_bytes(32));"
   ```

3. จะได้ตัวอักษร 0-9 a-f ยาว 64 ตัว เช่น `3f9a0c...e71b` → คัดลอกจดไว้เป็น **SHARED_SECRET**

**วิธี ข — ไม่มี XAMPP:** ใช้โปรแกรมจัดการรหัสผ่านสร้างรหัสสุ่มยาว 64 ตัว (ใช้เฉพาะ a-z, 0-9)

> 🔒 คีย์นี้เทียบเท่ารหัสผ่านของระบบไฟล์ทั้งหมด ห้ามส่งในกลุ่ม LINE, ห้าม commit ลง Git,
> ห้ามใส่ในไฟล์อื่นนอกจาก Script Properties และ `config/local.php`

## ขั้นที่ 5: ตั้งค่า Script Properties และ Time zone

1. ในหน้า Apps Script แถบซ้ายสุด คลิกไอคอน **⚙️ การตั้งค่าโปรเจกต์ (Project Settings)**
2. หัวข้อ **ทั่วไป (General settings)** → **เขตเวลา (Time zone)** เลือก `(GMT+07:00) Bangkok`
3. เลื่อนลงล่างสุด หัวข้อ **พร็อพเพอร์ตี้ของสคริปต์ (Script Properties)** → **แก้ไขพร็อพเพอร์ตี้ของสคริปต์** → **เพิ่มพร็อพเพอร์ตี้**
   เพิ่มทีละแถว (ชื่อพร็อพเพอร์ตี้ต้องพิมพ์ตัวใหญ่ตรงตามนี้):

   | พร็อพเพอร์ตี้ (Property) | ค่า (Value) |
   |---|---|
   | `SHARED_SECRET` | คีย์ลับจากขั้นที่ 4 |
   | `ROOT_FOLDER_ID` | รหัสโฟลเดอร์จากขั้นที่ 1 |
   | `CALENDAR_ID` | รหัสปฏิทินจากขั้นที่ 2 (ไม่ใช้ก็ไม่ต้องเพิ่มแถวนี้) |

4. กด **บันทึกพร็อพเพอร์ตี้ของสคริปต์ (Save script properties)**

> ⚠️ ระวังช่องว่างหน้า/หลังค่าที่วาง เป็นสาเหตุอันดับ 1 ของข้อผิดพลาด "ลายเซ็นไม่ถูกต้อง"

---

## ขั้นที่ 6: ตรวจการตั้งค่าด้วย checkSetup (และอนุญาตสิทธิ์)

1. แถบซ้าย คลิกไอคอน **< > ตัวแก้ไข (Editor)** กลับไปที่ `Code.gs`
2. แถบเครื่องมือด้านบน ช่องเลือกฟังก์ชัน (ข้างปุ่ม Debug) เลือก **`checkSetup`** → กด **▶ เรียกใช้ (Run)**
3. ครั้งแรกจะมีหน้าต่าง **ต้องมีการให้สิทธิ์ (Authorization required)**:
   1. กด **ตรวจสอบสิทธิ์ (Review permissions)** → เลือก **บัญชีกลาง**
   2. ถ้าขึ้น **"Google ไม่ได้ยืนยันแอปนี้" (Google hasn't verified this app)**:
      กด **ขั้นสูง (Advanced)** → **ไปที่ SmartSEC Bridge (ไม่ปลอดภัย)**
      (เป็นเรื่องปกติของสคริปต์ที่องค์กรเขียนใช้เอง)
   3. ตรวจรายการสิทธิ์ (Drive, Calendar, ส่งอีเมล) → กด **อนุญาต (Allow)**
4. ดูผลที่ **บันทึกการดำเนินการ (Execution log)** ด้านล่าง ควรเห็นประมาณนี้:

   ```
   ✅ SHARED_SECRET ยาว 64 ตัวอักษร (ต้องอย่างน้อย 32)
   ✅ SHARED_SECRET ไม่มีช่องว่างหน้า/หลัง
   ℹ️ บัญชีที่รันสคริปต์: smartsec-bot@py-sec.ac.th
   ℹ️ Time zone ของโปรเจกต์: Asia/Bangkok (ควรเป็น Asia/Bangkok)
   ✅ ROOT_FOLDER_ID: โฟลเดอร์ "SmartSEC-Files" สร้างและลบไฟล์ได้
   ✅ CALENDAR_ID: ปฏิทิน "ปฏิทินกลาง ศูนย์การศึกษาพิเศษ"
   ℹ️ โควตาอีเมลที่เหลือวันนี้: 1500
   🎉 พร้อมใช้งาน — ขั้นต่อไป: Deploy เป็น Web app
   ```

   ถ้ามี ❌ ให้แก้ตามข้อความ แล้วกด Run ใหม่จนผ่านทั้งหมด

## ขั้นที่ 7: Deploy เป็น Web App

1. มุมขวาบน กด **การทำให้ใช้งานได้ (Deploy)** → **การทำให้ใช้งานได้รายการใหม่ (New deployment)**
2. ข้างคำว่า "เลือกประเภท" กดไอคอน **⚙️** → เลือก **เว็บแอป (Web app)**
3. กรอก:
   - **คำอธิบาย:** `v1`
   - **ดำเนินการในฐานะ (Execute as):** **ฉัน (Me)** — บัญชีกลาง
   - **ผู้ที่มีสิทธิ์เข้าถึง (Who has access):** **ทุกคน (Anyone)**
4. กด **ทำให้ใช้งานได้ (Deploy)**
5. คัดลอก **URL ของเว็บแอป (Web app URL)** ที่ลงท้ายด้วย **`/exec`** จดไว้

   ```
   https://script.google.com/macros/s/AKfycbx...ยาวมาก.../exec
   ```

> **ทำไมต้องเลือก "ทุกคน (Anyone)"?** โฮสต์เรียก Bridge แบบเครื่องต่อเครื่อง ไม่มีการล็อกอิน Google
> ความปลอดภัยมาจากลายเซ็นคีย์ลับ และ Bridge เข้าถึงได้เฉพาะไฟล์ในโฟลเดอร์ `ROOT_FOLDER_ID` เท่านั้น
>
> **ถ้าไม่มีตัวเลือก "ทุกคน" (มีแค่ "ทุกคนใน py-sec.ac.th"):** ผู้ดูแล Google Workspace ขององค์กรปิดไว้
> ให้แจ้งผู้ดูแลไปที่ Admin console → Apps → Google Workspace → Drive and Docs → Sharing settings
> แล้วอนุญาตการแชร์ภายนอกให้บัญชีกลาง (หรือ OU ของบัญชีกลาง) จากนั้น Deploy ใหม่

## ขั้นที่ 8: ใส่ค่าในระบบ (config/local.php บนโฮสต์)

1. เข้า **cPanel → File Manager** → โฟลเดอร์ของระบบ → `config/` → คลิกขวา `local.php` → **Edit**
   (ถ้ายังไม่มีไฟล์นี้ ให้คัดลอก `local.example.php` เป็น `local.php` ก่อน)
2. เพิ่ม 3 ส่วนนี้ **ก่อนบรรทัดสุดท้าย `];`** ระวังเครื่องหมาย `,` ท้ายแต่ละส่วน:

   ```php
       'google' => [
           'apps_script_url' => 'https://script.google.com/macros/s/AKfycbx.../exec',
           'shared_secret' => 'วางคีย์ลับจากขั้นที่ 4 ตรงนี้',
       ],
       'mail' => [
           'driver' => 'apps_script',
       ],
   ```

   และในส่วน `'app' => [...]` ที่มีอยู่แล้ว เพิ่มบรรทัด URL ของระบบ (ใช้สร้างลิงก์ในอีเมล):

   ```php
       'app' => [
           'env' => 'production',
           'debug' => false,
           'key' => '...ค่าเดิม ห้ามเปลี่ยน...',
           'url' => 'https://smart.py-sec.ac.th',
       ],
   ```

   ตัวอย่างไฟล์ทั้งไฟล์หลังแก้:

   ```php
   <?php

   declare(strict_types=1);

   return [
       'app' => [
           'env' => 'production',
           'debug' => false,
           'key' => '...ค่าเดิม...',
           'url' => 'https://smart.py-sec.ac.th',
       ],
       'database' => [
           'host' => 'localhost',
           'name' => '...',
           'user' => '...',
           'pass' => '...',
       ],
       'session' => [
           'secure' => true,
       ],
       'google' => [
           'apps_script_url' => 'https://script.google.com/macros/s/AKfycbx.../exec',
           'shared_secret' => '3f9a0c...e71b',
       ],
       'mail' => [
           'driver' => 'apps_script',
       ],
   ];
   ```

3. กด **Save Changes**

> ⚠️ ถ้าบันทึกแล้วหน้าเว็บขาว/Error 500 แปลว่าไวยากรณ์ PHP ผิด (มักลืม `,` หรือ `'`)
> ให้เปิดไฟล์ตรวจใหม่ หรือกู้จากไฟล์สำรองที่ควรคัดลอกไว้ก่อนแก้
>
> 🖥️ **เครื่อง local (XAMPP):** ใช้ `'mail' => ['driver' => 'log']` อีเมลจะถูกเขียนลง `storage/logs/mail.log`
> แทนการส่งจริง ส่วน Drive/Calendar ใช้ URL และคีย์ชุดเดียวกับโฮสต์ได้

## ขั้นที่ 9: ทดสอบจากระบบ

1. ล็อกอินระบบด้วยบัญชี Super Admin → เมนู **ตั้งค่าระบบ**
2. การ์ด **Google Workspace** ด้านบน ต้องขึ้น "ตั้งค่าแล้ว" → กด **ทดสอบการเชื่อมต่อ**
3. ผลที่ถูกต้อง:
   > เชื่อมต่อ Google Workspace สำเร็จ — บัญชี: smartsec-bot@... · โฟลเดอร์ Shared Drive: SmartSEC-Files · ปฏิทิน: ปฏิทินกลาง... · โควตาอีเมลวันนี้: 1500
4. ทดสอบใช้งานจริง:
   - [ ] เมนู **ไฟล์/เอกสาร** → อัปโหลด PDF เล็กๆ → เปิดดู/ดาวน์โหลดได้ → ไปดูใน Shared Drive ต้องมีไฟล์ใน `core/ปี-เดือน`
   - [ ] เมนู **ปฏิทินกลาง** → เพิ่มกิจกรรมระดับ "ทั้งองค์กร" → ไปดูใน Google Calendar ต้องมีกิจกรรมนั้น
   - [ ] เมนู **คำขอใช้สิทธิ์ PDPA** → ยื่นคำขอทดสอบ → ผู้ดูแลต้องได้อีเมลแจ้งเตือน (ดูในจดหมายขยะด้วย)
   - [ ] ลบไฟล์/กิจกรรม/คำขอทดสอบเมื่อเสร็จ

## การแก้โค้ด Apps Script ภายหลัง (สำคัญ)

เมื่อมีโค้ด `Code.gs` เวอร์ชันใหม่จากโปรเจกต์ **การกดบันทึกอย่างเดียวยังไม่มีผล** ต้องออกเวอร์ชันใหม่:

1. วางโค้ดใหม่ทับทั้งหมด → บันทึก → Run `checkSetup` อีกครั้ง (ถ้าโค้ดใหม่ขอสิทธิ์เพิ่ม จะมีหน้าต่างอนุญาต)
2. **Deploy → จัดการการทำให้ใช้งานได้ (Manage deployments)**
3. เลือกรายการเดิม → ไอคอน **✏️ แก้ไข** → **เวอร์ชัน (Version): เวอร์ชันใหม่ (New version)** → **Deploy**

URL `/exec` เดิมใช้ต่อได้ ไม่ต้องแก้ `config/local.php`
(ห้ามกด "New deployment" ซ้ำ เพราะจะได้ URL ใหม่ ซึ่งต้องไปแก้ config ด้วย)

## การเปลี่ยนคีย์ลับ (เมื่อสงสัยว่าคีย์รั่ว)

1. สร้างคีย์ใหม่ (ขั้นที่ 4)
2. แก้ `SHARED_SECRET` ใน Script Properties → บันทึก
3. แก้ `shared_secret` ใน `config/local.php` ทันที (ระหว่างนี้การอัปโหลด/อีเมลจะล้มเหลวชั่วคราว)
4. กด **ทดสอบการเชื่อมต่อ** ในระบบ

## แก้ปัญหาที่พบบ่อย

| ข้อความที่เห็นในระบบ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ยังไม่ได้ตั้งค่าการเชื่อมต่อ Google Workspace | `config/local.php` ไม่มีส่วน `google` หรือคีย์สั้นกว่า 32 ตัว | ทำขั้นที่ 8 |
| apps_script_url ต้องเป็น https:// | URL พิมพ์ผิด/ไม่ครบ | คัดลอก Web app URL ใหม่จากขั้นที่ 7 |
| ตอบกลับไม่ใช่ JSON (HTTP 401/403/404) | Who has access ไม่ใช่ "Anyone", ใช้ URL ที่ลงท้าย `/dev` หรือ URL ของ deployment ที่ลบไปแล้ว | Deploy ให้ถูกตามขั้นที่ 7 และใช้ URL ลงท้าย `/exec` |
| ลายเซ็นไม่ถูกต้อง | คีย์ใน Script Properties กับ `config/local.php` ไม่ตรงกัน (มักมีช่องว่างเกิน) | วางคีย์ใหม่ทั้งสองที่ แล้ว Run `checkSetup` |
| คำขอหมดอายุ (เวลาเครื่องไม่ตรงกัน) | นาฬิกาโฮสต์คลาดเกิน 5 นาที | แจ้งผู้ให้บริการโฮสต์ให้ตั้งเวลาเซิร์ฟเวอร์อัตโนมัติ (NTP) |
| ยังไม่ได้ตั้ง SHARED_SECRET | ลืมเพิ่ม Property หรือสะกดชื่อผิด | ทำขั้นที่ 5 (ชื่อต้องเป็นตัวใหญ่ตรงตามตาราง) |
| No item with the given ID / Access denied: DriveApp | `ROOT_FOLDER_ID` ผิด หรือบัญชีกลางไม่ได้เป็นสมาชิก Shared Drive | ตรวจขั้นที่ 1 ข้อ 5–6 |
| ไม่พบ Google Calendar ตาม CALENDAR_ID | รหัสปฏิทินผิด หรือบัญชีกลางไม่มีสิทธิ์แก้ไขปฏิทิน | ตรวจขั้นที่ 2 หรือลบ Property `CALENDAR_ID` ถ้าไม่ใช้ |
| ไม่อนุญาตให้เข้าถึงไฟล์นอกโฟลเดอร์ของระบบ | ไฟล์ถูกย้ายออกจาก `SmartSEC-Files` ใน Drive | ย้ายไฟล์กลับเข้าโฟลเดอร์เดิม (อย่าจัดไฟล์ในโฟลเดอร์นี้ด้วยมือ) |
| Authorization is required / ต้องการการให้สิทธิ์ | โค้ดใหม่ขอสิทธิ์เพิ่ม แต่ยังไม่ได้อนุญาต | Run `checkSetup` ใน Editor เพื่ออนุญาต แล้วออกเวอร์ชันใหม่ |
| Service invoked too many times / quota | ใช้เกินโควตารายวันของ Google | รอวันถัดไป (รีเซ็ตทุก 24 ชม.) |
| อัปโหลดแล้วหน้าเว็บค้าง/Error 500 กับไฟล์ใหญ่ | `memory_limit` หรือ `upload_max_filesize` ของโฮสต์ต่ำ | ขอผู้ให้บริการปรับ `memory_limit ≥ 256M`, `upload_max_filesize` และ `post_max_size ≥ 25M` |
| ระบบแจ้งว่าส่งแล้ว แต่ไม่ได้รับอีเมล | อีเมลเข้าจดหมายขยะ หรือผู้รับไม่มีอีเมลในระบบ | ตรวจ Spam และตรวจว่าบัญชีผู้ใช้มีอีเมล |

ดูรายละเอียดข้อผิดพลาดเพิ่มเติมได้ที่ Apps Script → แถบซ้าย **การดำเนินการ (Executions)**
จะเห็นทุกคำขอที่เข้ามาพร้อมข้อความ error

## ข้อจำกัดของ Google ที่ควรรู้

- ไฟล์ละไม่เกิน **20 MB** (ระบบตรวจทั้งฝั่ง PHP และ Apps Script)
- อีเมลส่งได้ประมาณ **1,500 ผู้รับต่อวัน** (Google Workspace)
- คำขอหนึ่งครั้งทำงานได้ไม่เกิน **6 นาที**
- ไฟล์ที่ลบในระบบจะไปอยู่ในถังขยะของ Shared Drive และกู้คืนได้ภายใน 30 วัน
